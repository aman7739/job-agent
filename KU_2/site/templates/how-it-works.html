System Architecture & Processing Pipeline

An end-to-end technical overview of how the Job Digest Agent collects, normalizes, evaluates, and delivers verified tech opportunities twice daily for a final-year B.Tech CSE (Batch 2027) graduate.

1

Stage 1: Multi-Source Ingestion with Fault Isolation

The runner executes concurrent asynchronous requests across 8 permitted source adapters: Greenhouse, Lever, Ashby, SmartRecruiters, Workable, Adzuna, Remotive, and SSL IMAP Email alerts. Each source executes within an isolated try-except fault boundary.

If an individual ATS API experiences rate limits, network timeouts, or schema variations, the failure is recorded to the source_runs database table while all other sources continue uninterrupted. Unreachable sources are explicitly named in the digest header so the candidate always knows pipeline health.

2

Stage 2: Text Normalization, Location Cleaning & Anti-Traps

Raw job postings contain erratic formatting, tracking parameters, and HTML artifacts. The normalization engine cleans every record:

  • Sanitization: Strips HTML tags, decodes character entities, and removes marketing trackers (UTM parameters, ref tokens).
  • Location Canonicalization: Resolves alternate metro spellings (e.g., Gurgaon → Gurugram, Calcutta → Kolkata, Bangalore → Bengaluru).
  • Salary & Stipend Extraction: Parses LPA ranges, annual CTC figures, and monthly internship stipends into normalized INR amounts.
  • Anti-Trap Regex: Word-boundary regex matching ensures single-letter technologies like C and short tokens like Go are never mistakenly matched inside ordinary English words like CSS, Google, or Ongoing.
3

Stage 3: SHA-256 Deduplication & 48-Hour Freshness Cutoff

Job aggregators and corporate ATS platforms frequently repost the same opening under slight name variations (e.g., "Stripe" vs "Stripe India Private Limited"). The agent strips legal suffixes (Inc., Ltd., Pvt Ltd) to form a canonical corporate brand before computing a deterministic fingerprint:

fingerprint = sha256(canonical_company | normalized_title | canonical_location)

Any posting published more than 48 hours prior to the run is discarded to guarantee only fresh listings are delivered. Postings previously recorded in the database are filtered out to eliminate duplicate alerts.

4

Stage 4: Hard Filters & Deterministic 10-Point Scoring

Before scoring, every opportunity passes through strict eligibility filters: Senior, Staff, Lead, Architect, and Manager roles are discarded; postings demanding > 2 years of professional experience are excluded; and candidate batch restrictions ensure alignment with 2027 graduation. Surviving jobs are evaluated against a transparent 10-point scoring algorithm:

Category Max Points Scoring Criteria
Skills Overlap 4.0 pts Matches candidate stack (Python, FastAPI, PostgreSQL, React, Linux, Docker, REST APIs). 4+ matches receive full 4.0 pts; 3 matches receive 3.0 pts; 2 matches receive 2.0 pts; 1 match receives 1.0 pt.
Role Match 3.0 pts Software Engineer, Backend Developer, Full Stack Engineer, or Systems Engineer titles receive 3.0 pts.
Experience Level 2.0 pts Internships, Apprenticeships, Graduate Engineer Trainee, or 0-year Fresher roles receive full 2.0 pts.
Location Match 1.0 pt Roles based in Delhi NCR, Bengaluru, Mumbai, Pune, Kolkata, Indore, or Remote receive 1.0 pt.
5

Stage 5: Dual-Channel Delivery & Fast-Track Urgency Alerts

Digests are formatted into dual active sections: Internships & Apprenticeships and Full-Time Fresher Roles. Opportunities meeting the minimum score threshold (7.0 / 10) are delivered on a scheduled cadence and expedited when closing soon:

  • Twice-Daily Cadence: Automated scheduled runs at 08:00 AM IST and 07:00 PM IST ensure the candidate reviews fresh openings before business hours and at the close of the workday.
  • Immediate Urgent Alerts: Listings with stated deadlines closing in ≤ 4 hours bypass the batch schedule and dispatch an immediate high-priority alert to Telegram and Email.
  • On-Demand Execution: The private web dashboard includes a ⚡ Check & Notify Now button allowing the candidate to trigger an immediate crawl and delivery on demand.
  • Message Integrity: Telegram payloads exceeding 4,096 characters are cleanly partitioned along paragraph and line breaks so markdown links are never truncated.
